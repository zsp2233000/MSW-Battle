# 地圖與編隊規範

`map/map01.map`、`map/formationsim.map` 與 `map/matchprobe.map` 共用中央原點地形與 BattleCameraAnchor。#35／#37 明確授權取代原「保留舊地形、不重製地形」限制；仍保留 ADR 0001 的 RectTile／Kinematicbody 決策。#36 已於 2026-10-23 通過 Maker 雙視角技術驗證並結案，正式重畫在此之後執行。

| 項目 | 基準 |
|---|---|
| TileMapMode | 1 / RectTile，無重力 |
| 可行走戰鬥內場 | 30 × 16，共 480 個地塊 |
| 內場格點 | X=-15..14，Y=-8..7 |
| GridSize | 1 × 1 世界單位 |
| 內場世界邊界 | X=[-15,15)，Y=[-8,8)，實際中心 (0,0) |
| 外牆 | 格點 X=-16／15、Y=-9／8，共 96 塊，另建於內場之外 |
| 玩家展示區 | 格點 X=-15..14、Y=9..10，共 60 塊；旁觀位置 (-6.5,9.5)；不接受部署 |
| 原生格點轉換 | IsOddGridPosition=false；格點 (x,y) 中心為世界 (x+0.5,y+0.5)；鏡射格點 (-x-1,y) |
| 地塊容器 | Transform 保持 (0,0,1000)，未平移、縮放地塊容器 |
| 地形總數 | 636；原有 tileset 的可行走地塊 93、牆壁 47（檔案索引） |
| 相機 | Anchor=(0,0,0)，CameraOffset=(0,0)，ZoomRatio=32；固定鏡頭、Cut、blendTime=0 |

地塊格線是地形資料，並非布陣槽位。保存 `monsterId`、`x`、`y` 的原始連續世界座標，不取整、吸附、縮放或重排。MSW Vector3 本身具有浮點精度差異；保存值須與收到的座標相同。每組仍為 1–6 個單位、共用 MonsterCatalog、同兵種可重複，最小間距 0.3。

伺服器僅接受單位中心 x<0，且 (x,y) 與 (-x,y) 同時在內場、存在原生地塊且不碰牆。x=0、右側、非有限值、外牆、缺失地塊及鏡射後非法均拒絕。x=-15 雖屬左側內場外框，鏡射到被排除的 x=15，故不可保存；x=-14.99、y=-8 與 x=-0.01、y=7.99 為正例。對手直接生成於 (-x,y)，不再由地形外框或牆壁推算中心。POC 新部署同樣限左半場；其六個固定敵軍依新座標重設。

模擬地圖預覽為客戶端純視覺實體，採用正式 catalog 待機動畫，不掛戰鬥、碰撞或 AI。左鍵選取／放置／移動；右鍵或工具列移除。選兵後可用左上方「收起整備面板」露出完整左半場，再以同一按鈕展開保存／啟用；收合保留兵種、單位選取與草稿。工具列覆蓋區不接受地圖放置。

資料以 `BattleFormationsV2`／schema=2、`BattleTransferV2`／coordinateSchema=2 及 queueName=`battle-centered-v2` 隔離。舊 V1 鍵不讀取、不遷移，舊五組內容及啟用選擇不再有效；舊 schema 或交接不能匯入新版。這是一次性的命名空間切換，非每次登入或回程清空。首次缺少新版鍵才從五空欄位、activeSlot=0 開始；逾時、讀取錯誤及損毀資料維持 ERROR，禁止覆寫。新版保存確認、啟用、固定本局編隊與同次登入草稿往返語意不變。

新增戰場透過 MapBuilder 從 map01 複製，保留地形、原點與 GridSize；改動可行走區時須重新驗證原點與鏡射落點，不能只比較外框大小。隔離的 `battleviewprototype` 保留 #36 舊地形，並非正式新版戰場。

驗證步驟與本次證據見 [Issue-37-Centered-Battlefield.md](Issue-37-Centered-Battlefield.md)。相機以 1920×1080 實測原生 ScreenToWorldPosition 為 (-20,-11.25)..(20,11.25)，涵蓋內場與上方角色展示。行動裝置適配與正式雙方呈現分屬後續範圍。
