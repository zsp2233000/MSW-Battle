## 1. 一句話概念

> 玩家在 `map01` 左側自由部署一至六隻怪物，開戰後觀看它們持續索敵、自動移動並對抗右側固定六隻敵軍，直到顯示勝利、失敗或平手。

## 2. 關鍵決策（不可變基線）

| 項目 | 決策 | 備註 |
|---|---|---|
| 相機／地圖模式 | `map01.map`、`RectTile`、固定全場相機 | 動態單位使用 `KinematicbodyComponent`；依 ADR 0001，不改成 MapleTile |
| 玩家 | 保留 `DefaultPlayer` 外觀，固定於戰場下方中央 | 不可移動、不可碰撞、不可被選為目標、不可受傷 |
| 單局形式 | 一次部署、一次自動戰鬥 | 開戰後不得改變編隊；POC 不設重開按鈕，重新 Play 開下一局 |
| 玩家數 | 單人對固定敵軍 | 戰鬥與結果由伺服器權威處理；同步必要狀態，不實作 PvP |
| 輸入 | PC 滑鼠 | 點擊怪物名稱選項、戰場位置、已部署單位與開始按鈕 |
| 優先順序 | 規則可玩、結果正確、完整呈現回饋 | 不建立養成、經濟、關卡選擇或內容量產系統 |
| 美術與 UI 權責 | 全部由人類提供及設計 | AI 不搜尋、生成、挑選或上傳 RUID／音效，也不設計或修改 UI 外觀、階層、文字 |

## 3. 核心循環（單局）

`進入 map01` → `選擇怪物名稱` → `在玩家部署區放置／移除 1–6 隻單位` → `按下開始` → `雙方自動索敵、移動、攻擊` → `任一方全滅` → `顯示 Win／Lose／Draw` → `所有 AI 停止`

## 4. 核心系統

### 4.1 戰鬥階段

| 階段 | 規則 |
|---|---|
| `DEPLOYMENT` | 玩家可配置玩家編隊；固定敵軍已存在；戰鬥 AI 停止 |
| `BATTLE` | 部署鎖定；雙方 AI 啟動；不可新增、移除或換位 |
| `RESULT` | 判定結果；所有移動、索敵、攻擊及坦克接觸命中停止 |

- 玩家未部署任何單位時不能開始。
- 玩家可部署一至六隻，同一怪物可重複選用，沒有種類配額。
- 固定敵軍永遠六隻；預設編成為坦克二、戰士二、射手二。
- 結果判定於同一批傷害完成後執行：敵軍全滅為 Win、玩家編隊全滅為 Lose、同批全滅為 Draw。

### 4.2 部署

- 玩家部署區：`X = -5 至 -2`、`Y = -3 至 1`。
- 從怪物名稱選單選定 `MonsterId` 後，點擊玩家部署區放置該怪物；伺服器重驗證 `MonsterId` 與部署規則。
- 新單位與任何已部署單位至少相距 `0.6` 世界單位；不合法位置不放置。
- 部署階段點擊已部署單位會將它移除。
- 達六隻後拒絕新增；移除後可再放置。
- 固定敵軍的位置位於右側 `X = 1 至 3`、`Y = -3 至 1`，由可調設定保存，不允許玩家修改。

### 4.3 單位共通 AI

- 每 `0.5` 秒重新評估最近的存活敵人。
- 距離相同時保留目前目標，避免來回切換。
- 目標超出攻擊距離時，以直線向目標移動；沒有尋路。
- 單位彼此沒有物理阻擋，不推擠。
- 到達攻擊距離後停止前進並依冷卻攻擊。
- 目標死亡或失效時停止該次攻擊，於下一次索敵取得新目標。

### 4.4 怪物數值與種類

| 初始怪物名稱／種類 | HP | 移速 | 傷害 | 間隔 | 距離 | 行為 |
|---|---:|---:|---:|---:|---:|---|
| 坦克 | 500 | 1.1 | 40 | 每目標 2.0 秒 | 接觸 | 接觸命中沿用 `AttackDamage`，並將敵方擊退約 0.8 世界單位；不使用一般攻擊動畫 |
| 戰士 | 220 | 2.0 | 35 | 0.7 秒 | 0.6 | 近戰攻擊；命中時間由人類提供的攻擊動畫命中影格決定 |
| 射手 | 120 | 0.8 | 30 | 0.8 秒 | 4.0 | 瞬發命中，不建立投射物；命中時間由人類提供的攻擊動畫命中影格決定 |

- 表格是三筆初始怪物資料，不是種類預設值。同種類可新增多隻具名怪物，並各自設定數值與 RUID；種類只決定坦克、戰士或射手的戰鬥行為。
- 所有傷害固定；沒有護甲、暴擊、隨機浮動或兵種剋制。
- 坦克接觸命中可同時傷害所有重疊的敵方單位，各目標分別計算兩秒冷卻；傷害值使用共用的 `AttackDamage`。
- 坦克碰撞時只有敵方被擊退；坦克不後退。
- 擊退不造成暈眩；目標以速度與衰減完成擊退，位置限制於戰場內。
- 任何單位經 HitEvent 成功受傷後，受擊單位在原地停止 0.2 秒，再恢復索敵與移動；死亡狀態優先於 hit stop。
- 坦克接觸仍不播放碰撞特效或碰撞音效；坦克／射手的 attack、onhit、die SFX 僅在各自 RUID 有值時播放。
- 坦克接觸依陣營判定目標：同陣營 Tank 不會互相造成 Hit；若未來生成敵對陣營 Tank，則會依相同接觸 Hit 流程處理。
- 所有兵種的傷害都經由標準 Attack → Hit 流程處理，不直接改寫 HP；坦克以接觸觸發命中。

### 4.5 動畫與呈現資產契約

人類提供下列資產；AI 只保存 RUID、切換狀態、播放及更新功能值。

| 類別 | 人類提供內容 | 系統使用方式 |
|---|---|---|
| 每隻怪物的動畫 | 坦克填 `stand`、`move`、`hit`、`die`；戰士／射手另填 `attack` AnimationClip RUID | RUID 存於怪物資料列；不同怪物可填相同 RUID，坦克不需 `attack` |
| HP 條 | 背景與填充值各 1 個 Sprite RUID | 顯示於單位上方；系統只依 HP 比例縮放填充值 |
| 傷害數字 | 1 個 DamageSkin RUID | 每次成功傷害顯示固定傷害值 |
| 命中特效 | `HitEffectRUID` 可留空 | 有值時由攻擊者的怪物資料列決定，特效掛在被擊中的目標 Entity 上；空白時使用攻擊器的預設特效，若預設為 `TBD` 則略過；可重複使用相同 RUID |
| 音效 | `AttackSoundRUID`、`OnHitSoundRUID`、`DieSoundRUID` 可各自留空 | 有值時由怪物資料列決定並播放；空白時略過該音效，不依種類推導 |

- 戰士與射手的傷害在 `attack` 動畫命中影格發生，不以整段動畫結束時間代替。
- 系統依 AnimationClip 影格時間換算命中時間。
- 死亡單位先停止 AI、碰撞與受傷；客戶端在 `die` 動畫播放結束事件後隱藏，不以固定 `DeathHold` 秒數代替。伺服器不得以客戶端事件決定存活或勝負。
- 受擊時先在命中位置停留 0.2 秒；若同時有擊退，擊退完成後在新位置進入 hit stop，期間播放 `hit` 動畫。

### 4.6 UI 契約

人類建立 `.ui` 階層、版面、文字與視覺，交付可重複使用的怪物選項樣板／容器。程式依怪物資料列顯示名稱並綁定 `MonsterId`，不自行設計選項外觀。

| 實體名稱 | 用途 |
|---|---|
| 怪物選項樣板／容器 | 依怪物 dataset 產生名稱選項；選擇時保存對應 `MonsterId`，可容納同種類的多隻怪物 |
| `BtnStart` | 玩家至少部署一隻後可開始 |
| `ResultWin` | Win 狀態顯示 |
| `ResultLose` | Lose 狀態顯示 |
| `ResultDraw` | Draw 狀態顯示 |

- 既有 `BtnTank`、`BtnAssault`、`BtnShooter` 是舊版種類選擇介面；新怪物選單完成前可留作歷史實作，不作為新驗收契約。
- 進入地圖時三個結果實體皆停用。
- 產生結果時只啟用對應的結果實體。
- 戰鬥開始後，所有部署操作均由邏輯拒絕；按鈕如何呈現停用狀態由人類決定。

| HP 條 | 單位下的世界空間子 Entity；兩個人類提供的 Sprite RUID，填充值依 HP 比例縮放 |

| 特效／音效 | `BattleHitEffectPresentation` 將攻擊者的 hit Effect RUID 掛到受擊目標；`TankPresentation` 與 `ShooterPresentation` 播放已提供的 attack／onhit／die SFX；音效空白時略過，命中特效空白時使用攻擊器預設值；碰撞音效仍不使用 |
| UI | `BattleGroup.ui` 保留但隱藏；Issue #5 不綁定部署按鈕、開始按鈕或結果 UI |
| 相機與玩家 | 固定相機顯示完整戰場；停用 DefaultPlayer 移動與碰撞，使其不進入戰鬥查詢 |

## 7. 怪物資料契約

- M1 建立一份 `MonsterData` UserDataSet／CSV，每個 `MonsterId` 一列；初始三列分別顯示為坦克、戰士、射手。`MonsterId` 是不隨名稱變更的查找鍵，`MonsterName` 可修改，`MonsterType` 目前只接受 `TANK`、`ASSAULT`（顯示為戰士）、`SHOOTER`。
- 每列獨立保存 `MaxHp`、`MoveSpeed`、`AttackDamage`、`AttackIntervalSeconds`、`AttackRange`、`AttackImpactFrame`、接觸冷卻／範圍／擊退數值，以及該怪物的 `stand`／`move`／`attack`／`hit`／`die` 動畫、命中特效、攻擊／受擊／死亡音效 RUID。所有攻擊共用 `AttackDamage`；坦克保留接觸觸發，沒有另一個接觸傷害欄位。`HitEffectRUID` 與三個 SFX 欄位可各自留空；其他欄位仍依資料驗證規則處理。各欄分開保存；不同怪物可重複使用相同 RUID，不從種類繼承數值或資產。
- `AttackImpactFrame` 由人類填寫，空白時以第 1 幀為預設。坦克接觸命中不依賴一般攻擊動畫或命中影格，可留空或填 `0`。傷害仍由伺服器權威結算；戰士／射手須在 Maker Play 驗證動畫影格到伺服器命中時間的換算，不能以固定秒數冒充命中影格。
- 怪物資料列缺少 `MonsterId`、重複 ID、種類非法或必要數值無效時拒絕使用並給出明確錯誤。`HitEffectRUID`、`AttackSoundRUID`、`OnHitSoundRUID`、`DieSoundRUID` 可留空；資料表欄位仍須保留。其他資產不由程式搜尋、生成或猜測。
- 玩家與敵軍可引用同一個 `MonsterId`。玩家從依資料列產生的名稱選單選怪物；目前固定六隻敵軍的 ID 與位置、部署邊界和索敵間隔仍由戰局設定管理，不建立編隊 dataset。
- HP 條與 DamageSkin 目前各只有一種固定樣式，由既有／人類交付的 component 配置，不放入怪物 dataset，也不建立共用呈現 dataset。
- 死亡時伺服器立即停止玩法行為；客戶端依死亡動畫結束事件隱藏。怪物資料表不要求手填死亡秒數。
