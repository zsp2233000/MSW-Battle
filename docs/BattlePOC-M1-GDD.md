## 1. 一句話概念

> 玩家在 `map01` 左側自由部署一至六隻怪物，開戰後觀看它們持續索敵、自動移動並對抗右側固定六隻敵軍，直到顯示勝利、失敗或平手。

## 2. 關鍵決策（不可變基線）

| 項目 | 決策 | 備註 |
|---|---|---|
| 相機／地圖模式 | `map01.map`、`RectTile`、固定全場相機 | 動態單位使用 `KinematicbodyComponent`；依 ADR 0001，不改成 MapleTile |
| 玩家 | 保留 `DefaultPlayer` 外觀，固定於戰場下方中央 | 不可移動、不可碰撞、不可被選為目標、不可受傷 |
| 單局形式 | 一次部署、一次自動戰鬥 | 開戰後不得改變編隊；POC 不設重開按鈕，重新 Play 開下一局 |
| 玩家數 | 單人對固定敵軍 | 戰鬥與結果由伺服器權威處理；同步必要狀態，不實作 PvP |
| 輸入 | PC 滑鼠 | 點擊兵種按鈕、戰場位置、已部署單位與開始按鈕 |
| 優先順序 | 規則可玩、結果正確、完整呈現回饋 | 不建立養成、經濟、關卡選擇或內容量產系統 |
| 美術與 UI 權責 | 全部由人類提供及設計 | AI 不搜尋、生成、挑選或上傳 RUID／音效，也不設計或修改 UI 外觀、階層、文字 |

## 3. 核心循環（單局）

`進入 map01` → `選擇兵種` → `在玩家部署區放置／移除 1–6 隻單位` → `按下開始` → `雙方自動索敵、移動、攻擊` → `任一方全滅` → `顯示 Win／Lose／Draw` → `所有 AI 停止`

## 4. 核心系統

### 4.1 戰鬥階段

| 階段 | 規則 |
|---|---|
| `DEPLOYMENT` | 玩家可配置玩家編隊；固定敵軍已存在；戰鬥 AI 停止 |
| `BATTLE` | 部署鎖定；雙方 AI 啟動；不可新增、移除或換位 |
| `RESULT` | 判定結果；所有移動、索敵、攻擊及接觸傷害停止 |

- 玩家未部署任何單位時不能開始。
- 玩家可部署一至六隻，兵種可重複，沒有兵種配額。
- 固定敵軍永遠六隻；預設編成為坦克二、突擊二、射手二。
- 結果判定於同一批傷害完成後執行：敵軍全滅為 Win、玩家編隊全滅為 Lose、同批全滅為 Draw。

### 4.2 部署

- 玩家部署區：`X = -5 至 -2`、`Y = -3 至 1`。
- 選擇 `BtnTank`、`BtnAssault` 或 `BtnShooter` 後，點擊玩家部署區放置該兵種。
- 新單位與任何已部署單位至少相距 `0.6` 世界單位；不合法位置不放置。
- 部署階段點擊已部署單位會將它移除。
- 達六隻後拒絕新增；移除後可再放置。
- 固定敵軍的位置位於右側 `X = 1 至 3`、`Y = -3 至 1`，由可調設定保存，不允許玩家修改。

### 4.3 單位共通 AI

- 每 `0.5` 秒重新評估最近的存活敵人。
- 距離相同時保留目前目標，避免來回切換。
- 目標超出攻擊距離時，以直線向目標移動；沒有尋路。
- 單位彼此沒有物理阻擋，不推擠。
- 到達攻擊距離後停止前進並依冷卻攻擊。
- 目標死亡或失效時停止該次攻擊，於下一次索敵取得新目標。

### 4.4 兵種數值

| 兵種 | HP | 移速 | 傷害 | 間隔 | 距離 | 行為 |
|---|---:|---:|---:|---:|---:|---|
| 坦克 | 500 | 1.1 | 40 | 每目標 2.0 秒 | 接觸 | 無一般攻擊；與敵方重疊時造成固定傷害並將敵方擊退約 0.8 世界單位 |
| 突擊 | 220 | 2.0 | 35 | 0.7 秒 | 0.6 | 近戰攻擊；命中時間由人類提供的攻擊動畫命中影格決定 |
| 射手 | 120 | 0.8 | 30 | 0.8 秒 | 4.0 | 瞬發命中，不建立投射物；命中時間由人類提供的攻擊動畫命中影格決定 |

- 所有傷害固定；沒有護甲、暴擊、隨機浮動或兵種剋制。
- 坦克接觸可同時傷害所有重疊的敵方單位，各目標分別計算兩秒冷卻。
- 坦克碰撞時只有敵方被擊退；坦克不後退。
- 擊退不造成暈眩；目標以速度與衰減完成擊退，位置限制於戰場內。
- 坦克接觸不播放碰撞特效或音效，但仍更新 HP、顯示傷害數字，並讓敵方播放受擊／擊退動畫。
- 突擊與射手的傷害經由標準 Attack → Hit 流程處理，不直接改寫 HP。

### 4.5 動畫與呈現資產契約

人類提供下列資產；AI 只保存 RUID、切換狀態、播放及更新功能值。

| 類別 | 人類提供內容 | 系統使用方式 |
|---|---|---|
| 坦克動畫 | `stand`、`move`、`hit`、`die`，共 4 個 AnimationClip RUID | 坦克沒有 `attack` 動畫；擊退期間沿用 `hit` |
| 突擊動畫 | `stand`、`move`、`attack`、`hit`、`die`，共 5 個 AnimationClip RUID | `attack` 另提供命中影格 |
| 射手動畫 | `stand`、`move`、`attack`、`hit`、`die`，共 5 個 AnimationClip RUID | `attack` 另提供命中影格 |
| HP 條 | 背景與填充值各 1 個 Sprite RUID | 顯示於單位上方；系統只依 HP 比例縮放填充值 |
| 傷害數字 | 1 個 DamageSkin RUID | 每次成功傷害顯示固定傷害值 |
| 命中特效 | 1 個共用特效 RUID | 僅突擊與射手命中時播放；坦克接觸不播放 |
| 音效 | 突擊攻擊、射手攻擊、共用受擊、共用死亡音效 | 坦克造成接觸傷害時不播放攻擊、碰撞或受擊音效；其他符合狀態的事件正常播放 |

- 突擊與射手的傷害在 `attack` 動畫命中影格發生，不以整段動畫結束時間代替。
- 系統依 AnimationClip 影格時間換算命中時間。
- 死亡單位先停止 AI、碰撞與受傷，再播放完整 `die` 動畫；動畫播完才隱藏或移除。
- 受擊與擊退可同時發生；擊退移動期間播放 `hit` 動畫。

### 4.6 UI 契約

人類建立 `.ui` 階層、版面、文字與視覺。AI 不新增或修改其外觀，只為既有實體串接非視覺邏輯。

| 實體名稱 | 用途 |
|---|---|
| `BtnTank` | 選擇坦克 |
| `BtnAssault` | 選擇突擊 |
| `BtnShooter` | 選擇射手 |
| `BtnStart` | 玩家至少部署一隻後可開始 |
| `ResultWin` | Win 狀態顯示 |
| `ResultLose` | Lose 狀態顯示 |
| `ResultDraw` | Draw 狀態顯示 |

- 進入地圖時三個結果實體皆停用。
- 產生結果時只啟用對應的結果實體。
- 戰鬥開始後，所有部署操作均由邏輯拒絕；按鈕如何呈現停用狀態由人類決定。

## 5. 系統 ↔ MSW 對應（實際實作）

| 遊戲系統 | MSW 實作 |
|---|---|
| 全局階段與結果 | 伺服器權威 `@Logic` 管理 `DEPLOYMENT/BATTLE/RESULT`、存活數與同批結果判定；同步客戶端必要狀態 |
| 玩家輸入 | 客戶端 UI／滑鼠事件送出部署、移除與開始意圖；伺服器驗證階段、區域、數量與間距 |
| 單位模型 | 坦克、突擊、射手各用可重複生成的 `.model`；共同掛載生命、陣營、AI 與呈現元件 |
| 地圖物理 | `RectTile` 搭配 `KinematicbodyComponent`；不使用重力、跳躍或 foothold |
| 移動 | `MovementComponent` 逐幀朝目標方向移動；禁止用計時器跳位置或直接改 Transform 模擬移動 |
| 索敵與狀態 | 自訂 `@Component` 保存陣營、目前目標與 `IDLE/MOVE/ATTACK/HIT/DEAD`；每 0.5 秒掃描最近存活敵人 |
| 一般攻擊 | `AttackComponent`、`HitComponent` 與 Hit 事件鏈；攻擊動畫命中影格觸發固定傷害 |
| 坦克接觸 | `TriggerComponent` 重疊事件＋每目標冷卻表；經 Hit 流程造成傷害，使用 Kinematicbody 速度與衰減擊退敵方 |
| 射手 | 距離驗證後於命中影格直接命中目標；不建立投射物 Entity |
| 動畫 | `SpriteRendererComponent.SpriteRUID` 切換人類提供的 AnimationClip RUID；死亡依完整片長延遲移除 |
| HP 條 | 單位下的世界空間子 Entity；兩個人類提供的 Sprite RUID，填充值依 HP 比例縮放 |
| 傷害數字 | 使用人類提供的 DamageSkin RUID 與 MSW 傷害數字機制 |
| 特效／音效 | 命中與死亡事件呼叫 MSW 特效／音效服務；坦克造成接觸傷害的事件明確跳過特效與音效 |
| UI | 人類建立 `.ui`；客戶端綁定指定名稱的 Button／結果 Entity，只處理點擊、可用性與顯示狀態 |
| 相機與玩家 | 固定相機顯示完整戰場；停用 DefaultPlayer 移動與碰撞，使其不進入戰鬥查詢 |

## 6. Roadmap（本里程碑 Phases）

### Phase 1 — 一對一自動戰鬥垂直切片

- ✅ Tested 建立共用戰鬥階段、陣營、存活與結果狀態；Maker Play 已記錄 `BATTLE started` 與 `RESULT=WIN`。
- 🟡 Implemented (runtime path verified) 建立 RectTile／Kinematicbody 單位模型與逐幀直線移動；視覺位置觀察待補。
- 🟡 Implemented (runtime outcome verified) 完成一隻突擊對一隻突擊的 0.5 秒索敵、近戰攻擊、死亡與 Win／Lose 結果邏輯；逐次 native HitEvent timing log 待補。
- 🟡 Implemented (untested) 固定全場相機，保留但停用 DefaultPlayer 的移動、碰撞與戰鬥資格；Maker Play 視覺／互動確認待補。
- ✅ Tested 提供結果判定、AI 停止、Hit 流程及死亡後不可再次受傷的契約測試；Node 靜態契約與 Maker Play start/result/stop 均 PASS。

### Phase 2 — 玩家部署與六對六編隊

- ⬜ 串接人類提供的部署按鈕與開始按鈕 UI 實體。
- ⬜ 完成左側自由放置、點擊移除、0.6 最小間距、一至六隻限制與伺服器驗證。
- ⬜ 建立右側固定六隻敵軍與可調位置設定，預設二坦克、二突擊、二射手。
- ⬜ 開戰後鎖定所有部署操作。
- ⬜ 驗證一至六隻任意重複兵種皆能開始並完成單局。

### Phase 3 — 三兵種完整規則

- ⬜ 完成坦克高 HP、無一般攻擊、每目標兩秒接觸傷害。
- ⬜ 完成只擊退敵方約 0.8 世界單位、無暈眩、無單位阻擋及戰場邊界限制。
- ⬜ 完成突擊的近戰距離、攻擊間隔與命中影格傷害。
- ⬜ 完成射手的遠距瞬發命中、攻擊間隔與命中影格傷害。
- ⬜ 驗證固定傷害、無剋制／護甲／暴擊，以及同批全滅為 Draw。

### Phase 4 — 人類資產與完整戰鬥回饋

- ⬜ 人類提供 14 個 AnimationClip RUID、突擊／射手命中影格與各死亡動畫片長可讀資料。
- ⬜ 人類提供 HP 條背景／填充值、DamageSkin、共用命中特效及指定音效 RUID。
- ⬜ 人類建立並交付具有約定實體名稱、文字與外觀的 UI。
- ⬜ 串接 stand／move／attack／hit／die 動畫；坦克不建立 attack 動畫。
- ⬜ 串接世界 HP 條、傷害數字、突擊／射手命中特效、攻擊／受擊／死亡音效。
- ⬜ 確認坦克接觸只顯示傷害數字、更新 HP、播放敵方受擊／擊退動畫，不播放碰撞特效或音效。
- ⬜ 串接 `ResultWin`、`ResultLose`、`ResultDraw`，並驗證一次只顯示正確結果。

### Phase 5 — POC 驗收與範本清理

- ⬜ 完整測試部署、六對六自動戰鬥、三種結果、動畫時序、HP 條、傷害數字、特效、音效、死亡與擊退。
- ⬜ 測試零單位、第一隻／第六隻、距離邊界、同距離目標、重疊多目標、同批全滅與戰場邊界。
- ⬜ 列舉並檢查所有地圖；目前清單為 `map/map01.map`，移除確認為範本殘留的 Entity，驗證留下的每張地圖皆乾淨。
- ⬜ 由人類在 Maker Play 模式完成視覺、聲音、操作手感與整局驗收；AI 無法代替此項使用者測試。

## 7. 資料驅動

- M1 僅有三兵種與一組固定敵軍，不建立 UserDataSet／CSV。
- 單位數值、索敵間隔、部署邊界、敵軍位置、動畫 RUID、命中影格與音效／特效 RUID 集中於可調設定，不散落於多個腳本。
- 若未來增加大量兵種、關卡或平衡表，資料化工作放入里程碑 Roadmap，而非擴張本 GDD。
