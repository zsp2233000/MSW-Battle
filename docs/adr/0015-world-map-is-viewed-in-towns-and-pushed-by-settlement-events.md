# 國戰大地圖在城鎮中查看，戰果寫入後以事件推送戰況，不輪詢

Roadmap 原本把「國戰大地圖」放在 Backlog，呈現與操作形式待定。2026-11-24 使用者確認首版：依高雄行政區的實際排列畫四座城鎮，以連線表示相鄰；只能查看；在城鎮裡開啟，遊戲大廳不提供；戰況由伺服器推送給客戶端；底圖要有高雄地形。這份 ADR 記下做法，詞彙依 CONTEXT.md（國戰大地圖、據點、兵力值、主城、戰果）。

## 決定一：地圖是畫好的底圖加上執行時上色，相鄰關係取自傳送門

- 介面在 `ui/WorldMapGroup.ui`，由 `assets/worldmap/build_ui.cjs` 以 UIBuilder 產生；客戶端邏輯 `FactionWarMapUI` 以路徑找元件，和 `FactionWarUI` 相同。
- `assets/worldmap/paint_worldmap.cjs` 用 2×2 像素點畫出高雄 38 區。區界取自內政部國土測繪中心 [鄉鎮市區界線，1140318 版](https://data.gov.tw/dataset/7441)（[政府資料開放授權條款第 1 版](https://data.gov.tw/license)），以北上的等距圓柱投影簡化繪製，並保留壽山、半屏山、蓮池潭與愛河的示意細節。旗津顯示本島近岸部分，東沙、南沙不在同幅地圖範圍內。來源轉換方式見 `assets/worldmap/import_boundaries.py`。
- 底圖、四城的裁切遮罩與城徽上傳為帳號資源（RUID 記在 `assets/worldmap/ruids.json`）。地圖產生器以同一組投影輸出 `layout.json` 的標籤、城徽與遮罩座標；只有楠梓、左營、鼓山、鹽埕具有兵力、陣營著色與傳送門連線，其他區只供瀏覽。
- 固定矩形裁切範圍只移動地圖內容，不移動右側戰況。PC 滾輪以游標為中心縮放 1–12 倍，按住左鍵拖曳移動，邊界限制不露出底圖以外的空白；縮至最小或重開回到全覽。密集區名在放大後才顯示，文字不隨底圖等比放大。
- 連線不寫死在圖上：伺服器以 `FactionWar:FindGate` 列出任一方向有傳送門的城鎮對，客戶端在兩個城徽之間畫線。改了傳送門，地圖跟著改。

## 決定二：開著地圖的人才是訂閱者

按「大地圖」或 M 鍵時，客戶端呼叫 `FactionWarMap:RequestOpen`。伺服器確認玩家站在城鎮裡，記下他是這個靜態房的觀看者，讀一次城鎮文件後回傳戰況，另外讀一次他的陣營。關閉地圖、離開城鎮（客戶端在 `OnUpdate` 偵測到後關閉，並送 `RequestClose`）、離開這個房間（`UserLeaveEvent`）都會結束訂閱。

補記（#117，已由 #124 取代）：開著進攻面板的玩家是另一類觀看者，登記在 `FactionWarMap` 的 `panelViewers`（和地圖的 `viewers` 分開，地圖既有的訂閱行為不變）。進攻選項的回應已經讀過一次城鎮文件，所以面板的登記不再多讀一次；之後城鎮表變動時，面板收到各城的歸屬與兵力（`ReceivePanelBoard`）。關閉面板、離開城鎮、離開房間都會結束訂閱。

補記（#123）：攻城面板（排隊期間顯示在城鎮畫面上方的卡片）是第三類觀看者，登記在 `siegeViewers`，各自獨立：進攻面板與攻城面板可以同時開著，關掉其中一個不影響另一個（#124 起進攻面板已由地圖的選目標模式取代）。面板開始顯示時客戶端呼叫 `RequestSiegeOpen`（伺服器只認發送者、重複呼叫無害），伺服器讀一次城鎮表回覆；之後城鎮表變動時收到各城歸屬與兵力（`ReceiveSiegeBoard`，只有這些，沒有地圖連線與陣營）。面板隱藏（`RequestSiegeClose`）、離開城鎮、離開房間都會結束訂閱；重連會重啟客戶端，面板自己重新訂閱。已知限制：伺服器若無聲地丟掉訂閱（玩家實體換了），客戶端不會察覺，數字停在最後一次推送；排隊中的玩家不能離開城鎮，所以目前只有重連會發生，而重連會重新訂閱。

補記（#124）：進攻面板與 `panelViewers` 移除，改由國戰大地圖的**選目標模式**取代，觀看者只剩地圖（`viewers`）與攻城面板（`siegeViewers`）兩類。按城鎮 NPC 時，客戶端呼叫 `FactionWarAttack:RequestSelect`（取代 `RequestOptions`）：伺服器沿用 `Resolve` 只讀一次城鎮表與陣營，一次回覆狀態（`READY`／`ENGAGED`／`NOT_OWNED`／`UNAVAILABLE`）、出發城、可選目標，以及地圖用的戰況與連線；只有 `READY` 才以 `FactionWarMap:WatchMap` 把玩家登記為地圖觀看者（不再多讀一次）並開地圖，其他狀態只回狀態、不訂閱，客戶端改顯示只有「確定」的訊息視窗（地圖開著會擋住攻城面板的「取消配對」，所以不開）。#124 只做 `READY` 主路徑：其他狀態客戶端暫時什麼都不顯示（已開著的選目標模式收到非 `READY` 的回覆就關閉），訊息視窗與 NPC 守衛由後續的票補上。可選目標仍由伺服器的 `Targets`／`CanTarget` 決定，客戶端不自己用連線推相鄰；城鎮表的歸屬變動時，客戶端重新向伺服器要一次選項。選定目標後經確認視窗按「是」才呼叫 `RequestAttack`，收到 `QUEUING` 後關閉地圖。地圖、確認視窗或訊息視窗開著時，客戶端不處理兩個城鎮 NPC 的互動鍵（互動鍵事件不會被遮罩擋下，必須在 NPC 腳本明確判斷）。相對立場色、拔河條、點城徽選目標、目標失效處理也由後續的票實作，#124 的地圖仍用既有的陣營色與一般連線。以下是已定案的後續方向：顏色改為相對立場（我方藍、敵方紅），客戶端要先知道自己的陣營，所以 `RequestSelect` 與攻城面板訂閱的回覆都帶陣營；相鄰城之間的連線改為拔河條，紅藍交界位置依兩城兵力比例，兩端同立場時畫單色實線。

補記（#127）：非 `READY` 的回覆現在都開訊息視窗，不開地圖。`FactionWarAttack:SelectFor` 多了一種狀態 `NO_TARGETS`（出發城仍屬於自己，但沒有相鄰敵城，此時不登記觀看者、不開地圖），`ENGAGED` 的回覆在標頭帶 `target`（`MatchFlow:TargetForUser` 讀自己的戰爭票，沒有票時為空字串）。`FactionWarMapUI:ShowSelect` 對非 `READY` 的狀態先關閉已開著的選目標模式，再依 `MessageFor` 的文字呼叫 `ShowMessage`：已在排隊顯示「目前正在進攻 <城名>，要改變目標請先取消配對（畫面上方的攻城面板可以取消）」（沒有目標城時用不含城名的說法），出發城已失守「這座城已不屬於你的陣營」（仍照原規則交給 `FactionWarLanding:Judge` 判斷落點），無法讀取「暫時無法讀取國戰資料，請再試一次」，沒有相鄰敵城「目前沒有可進攻的相鄰敵城」；城名一律用 `FactionWarUI:HighlightedTownName` 的同一種高亮色。訊息視窗（`WorldMapGroup` 的 `Message`）是最後一個根節點，疊在地圖與確認視窗之上，只有「確定」一顆 Cardgame 按鈕，不需要地圖開著，按「確定」才關閉（出發城失守時玩家會立刻被落點判斷送回主城，訊息不能跟著城鎮消失）。NPC 守衛集中在 `FactionWarMapUI:BlocksInteraction`：地圖（含確認視窗）、訊息視窗，以及按下 NPC 後還沒收到回覆（`BeginSelect` 起算，超過 `AskTimeout` 秒仍沒有回覆就放棄）三種情況，國戰 NPC 與大廳 NPC 都不處理互動鍵，所以等待回覆期間再按不會有第二次請求或第二個視窗。地圖自己發出的重新取得選項（目標失效、易主）若在玩家關閉地圖後才回覆，非 `READY` 的回覆也不顯示訊息。

補記（#128）：選目標模式開著時戰果改變城鎮，畫面這樣收斂，可選目標仍只由伺服器決定。只有兵力變動：推送的戰況讓地圖、城鎮列與確認視窗的兩個數字即時更新，視窗不關、不再發請求。歸屬變動：`ShowBoard` 向伺服器重新要一次選項（`relistsOutstanding` 記還沒回覆的次數，每個回覆都算地圖自己的重新取得，連續兩次易主也是），`READY` 的回覆重畫可選清單、遮罩與地區顏色。側欄新增一行 `Overlay/Window/Side/Notice`（`SetNotice`，只有文字、不吃點擊）：選取中的目標不在新清單裡時，`SetMode` 丟掉選取（確認視窗隨之關閉），這一行顯示「<城名> 已不能進攻」；按「是」之後伺服器回 `INVALID`，`ShowAttackResult` 同樣結束「正在加入配對…」、關視窗、顯示這一行並重新要清單。這一行留到下一次點選、`READY` 清單又列出那座城、或地圖關閉；但「是」被拒絕（`INVALID`）時的這一行（`REFUSED`）不因清單又列出那座城而消失，只在下一次點選或地圖關閉時清除，因為玩家一定要知道這次進攻被拒絕了。出發城失守、玩家被送到主城後，來自主城的 `READY` 清單與目前的出發城不同時，`ShowSelect` 對新的出發城呼叫 `FocusOrigin`；出發城不變就不動玩家的視角。地圖自己發出的重新取得選項若被回覆 `NOT_OWNED`（出發城失守）或 `NO_TARGETS`（沒有目標了），不再像 #127 那樣關地圖改顯示訊息視窗，而是 `ShowNothingToPick`：地圖留著、確認視窗關閉、每一城都不可選（遮罩全開），`NOT_OWNED` 顯示「這座城已不屬於你的陣營」，`NO_TARGETS` 沿用「<城名> 已不能進攻」（沒有選取時為「目前沒有可進攻的相鄰敵城」）。失守時伺服器隨後仍用 `FactionWarLanding:Judge` 把玩家送回主城，之後的 `READY` 清單（來自主城）會清掉這一行。對 NPC 按鍵的回覆與 `ENGAGED`／`UNAVAILABLE` 的重新取得選項不變，仍走 #127 的訊息視窗。這一行是 `build_notice_ui.cjs` 以 UIBuilder 追加的新節點；Maker 以檔案內順序決定繪製順序，所以 `addNoticeUi` 把它排在 `Confirm` 與 `Message` 之前，兩個視窗仍在它之上。

補記（#129）：選目標模式一開啟就縮放到出發城，玩家也能直接點地圖上的城徽選取目標。`FactionWarMapUI:ShowSelect` 在選目標模式剛開啟（地圖本來關著，或從查看模式切過來）時呼叫 `FocusOrigin`，以 `SelectZoom`（4）倍、以出發城為中心呼叫既有的 `SetMapView`，所以邊界限制、標籤密度與滾輪、拖曳行為都沿用；已經在選目標模式時重新取得選項（目標失效、易主）不會把玩家移動過的視角拉回去；查看模式仍從全覽開始。點城徽不在城徽上放按鈕（地圖內容裡的控制項會攔截拖曳，這正是 `Map/Input` 固定輸入層存在的理由），而是由這個輸入層判斷：`BeginMapDrag` 記下按下的螢幕位置，`DragMap` 與 `EndMapDrag` 用 `MeasureTravel` 量指標離按下位置最遠多少螢幕像素，不超過 `ClickSlopPx`（10）才是點擊（`IsClick`；拖出去又回到原點仍算拖曳，量螢幕像素所以和縮放、解析度無關）。`ClickMap` 把放開位置轉到視窗座標、視窗外不算，取離該點最近且在命中半徑內的城徽（`TownAt`），最後呼叫 `Pick`：和城鎮列同一條路，確認視窗相同，伺服器沒列出的城鎮仍被拒絕，所以不可選的城徽點了沒有反應。命中半徑 `HitRadius` = `max(CrestHitReach × IconScale(zoom), MinHitPx ÷ 每 UI 單位的螢幕像素)`，`MinHitPx` 為 24 螢幕像素，詮釋為半徑（一個約 48 px 的圓，符合觸控目標大小），每 UI 單位的螢幕像素由 `ScreenPixelsPerUnit` 以螢幕寬度換算，所以任何縮放倍率與螢幕密度都點得中。外觀由 `CrestState`（`plain`／`selectable`／`selected`／`dimmed`）單一決定：暗化（沿用 #124）、列上的選取鈕與新的標記同源；每座城鎮節點多兩個隱藏子節點，`Mark`（標記，金色，可選的城徽）與 `Frame`（選取框，青色，選取中），都是比城徽大的城徽圖樣、畫在城徽後面成為一圈外框，由 `assets/worldmap/build_mark_ui.cjs`（只替換標記）與 `select_ui.cjs`（完整重建）產生。**不選**：在每個城徽上放 Button（擋住拖曳與滾輪）；按下即選（無法和拖曳區分）；用世界單位算命中範圍（縮放後小於手指）。

補記（#128 與 #129 合併）：兩張票共用 `CrestState`。`ShowNothingToPick` 把可選清單設為空，所以出發城失守或沒有目標時，每個城徽都是 `dimmed`（城徽、地區變暗、不顯示 `Mark`，點了沒反應），與列上的遮罩一致；選取中的目標失效時 `SetMode` 丟掉選取，`Frame` 隨確認視窗一起消失，不論當初是點列還是點城徽選的。

補記（#130）：地圖的查看模式與攻城面板訂閱都各自回覆玩家自己的陣營，分別走 `ReceiveFaction` 與 `ReceiveSiegeFaction`；戰況不等陣營讀完才回覆，後續推送也不重讀陣營。選目標模式沿用 `RequestSelect` 回覆的陣營。客戶端在各自的畫面保存陣營，`FactionWarUI:TownColor` 統一判斷立場：我方藍、敵方紅，未讀到或沒有陣營時用灰。城徽、區塊、城鎮列和攻城面板的兵力條都用此規則；「你的陣營」仍以金色顯示 A 方或 B 方，圖例改為「我方／敵方」。

## 決定三：戰果寫入後發事件，有觀看者的房間才重讀

`FactionWarAttack:Finish` 在 `SAVED` 或 `DUPLICATE` 時呼叫 `FactionWarMap:AnnounceChange`：

- 同一個 world instance：比賽房以 `RequestSendEventToRoomAsync` 通知靜態房，作法同 `TownFellEvent`（ADR 0012）；結算若就在靜態房，直接處理。
- 其他 world instance：以 `_WorldInstanceService:RequestSendEventToAllWorldInstancesAsync` 送 `TownBoardChangedEvent`，事件帶發送端的 `WorldInstanceId`（`Source`）。Maker 實測這個事件也會送回發送端自己的 instance，所以處理器略過 `Source` 等於自己 instance 的事件，這種事件已經用房間事件收過了。

收到通知的房間，沒有觀看者就什麼都不做，不花儲存額度。有觀看者就重讀城鎮文件，同一時間只讀一次，讀取中又來的通知會在讀完後再讀一次。讀到的戰況和上次推送的不同，才推給所有觀看者；剛開地圖的人一定會收到回覆。

**不選**：

- 定時輪詢城鎮文件：與 ADR 0012 和 `MatchFlow`「不做重複的儲存輪詢」相同理由，每個房間都要付固定額度。
- 把戰況直接放進事件：兩場結算的事件可能不按順序到達，較舊的戰況會蓋掉較新的。重讀已存的文件才是準的，也只多花一次讀取。
- 用 `@Sync` 屬性同步：table 不能同步，而且會送給房內所有客戶端，包括沒開地圖的人。

## 附帶效果

地圖開著時，推送來的戰況也會更新所在城鎮的 HUD 兵力（`FactionWarUI:ShowTownStatus`）。地圖沒開時，HUD 仍照 ADR 0012 的規則，只在進城與排隊回到 IDLE 時重讀。

## 已知缺口

- 只有戰果結算會發通知。`FactionWar:WriteTowns`（種子資料、測試夾具）不會通知；GM 也沒有改城鎮文件的工具。
- 事件送失敗不重試。少掉的那次變動，要等下一場戰果的通知或重開地圖才看得到。
- Maker 已驗證：真實比賽房的守衛戰結算後，房間事件送到靜態房，開著的地圖當場更新；本 instance 收到自己發出的 world-instance 事件時會略過。發布環境多個 instance 之間能否送達還沒驗證，留給 #110 雙帳號驗收時一起看。
- 失守城鎮的清掃（ADR 0012）仍只用房間事件，這份 ADR 沒有改它。
- M 鍵用 `KeyDownEvent` 偵測，腳本端沒有 API 能判斷輸入框是否有焦點。Maker 鍵盤模擬工具的說明提到，文字欄位有焦點時遊戲收不到按鍵，所以在聊天框打字時應該不會開關地圖，但沒有實測。
