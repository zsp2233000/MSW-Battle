# 怪物圖鑑在大廳本機試播，不跑真實戰鬥

開發者要在 Maker Play 看見每隻怪物的表現資源（動畫、出手與命中特效、投射物、音效）。圖鑑放在遊戲大廳的 UI 內，由 client 本機播放動畫並依戰鬥相同的時序觸發音效、特效與投射物，**不**另開地圖、也不生成真實戰鬥單位。時序不重算：怪物目錄載入時已算好 `ImpactDelaySeconds`、`AttackEffectDelaySeconds`、`AttackAnimationDurationSeconds`，圖鑑直接取同一組值；投射物飛行時間同為距離 ÷ `ProjectileSpeed`，距離取攻擊範圍（命中點，見 `CONTEXT.md`）。

`MonsterData` 維持 `serveronly`。圖鑑所需的 RUID 與上述數值只在 Maker Play 由伺服器回覆給 client；發布版沒有入口，伺服器也拒絕圖鑑請求。圖鑑唯讀，修改資源仍改資料表。

## 取捨

- 不選真實戰鬥沙盒（新地圖加兩隻真正的 `BattleUnit`）：需要 `BattleSession` 支援只有兩隻單位的場次、離開大廳換地圖，改動落在戰鬥伺服器上，風險遠大於這個開發者工具的價值；伺服器戰鬥邏輯本來就有 runtime probes。
- 代價是試播與戰鬥不是同一份程式，可能漂移。因此用一個 Maker probe，逐隻把圖鑑列的時序與真實戰鬥記錄的出手、特效、命中時間比對，漂移會讓驗證失敗。
- 不把 `MonsterData` 開放給 client：發布版會多出資料表外洩與請求面。只在 Maker Play 發布，等於功能與資料一起留在開發環境。
- 舞台用 UI 圖片而不是世界實體：大廳是純 UI 地圖，沒有可對位的相機。代價是 UI 渲染的錨點、縮放與翻轉可能與世界渲染不完全相同，大小與位置需要人工目視確認。

## 後果

- 圖鑑不驗證傷害、鎖定與取消等伺服器戰鬥邏輯。
- 怪物資料表新增與表現有關的欄位時，要同步更新圖鑑列、比對 probe 與契約測試。
- 發布版是否真的看不到入口、伺服器是否真的拒絕，Maker 內無法執行，只能用契約測試檢查結構，另靠發布後人工確認。
