# 射手投射物由出手者持有，抵達才結算傷害

GDD 原先決定射手「命中影格直接命中，不建立投射物」。月光／日光／星光精靈有 `attack1/info/ball` 動畫，需要看得見的飛行，所以改為**由資料列決定**：`MonsterData` 新增選填的 `ProjectileRUID`（AnimationClip）與 `ProjectileSpeed`（世界單位／秒）。留空維持原本的瞬發單體命中（血腥哈維、猴子不變）；填值的戰士或射手在**攻擊命中影格出手**，球追蹤出手時鎖定的目標，**抵達才結算傷害**。坦克不支援，載入時以 `CONFIG_ERROR` 拒絕。

球是出手者未完成的工作，不是獨立的戰場物件：它存在 `BattleAttackComposition` 裡，隨 `Advance` 前進，`Cancel`（出手者死亡、戰鬥結果、重新配置）一併丟棄且不造成傷害，沿用「未結算的出手不留存」的既有規則。目標在途中死亡或離場，球直接消失。抵達時由 `SingleTargetAttack` 在目標身體中心做一次原生 `Attack`，傷害區間、命中特效、受擊音效、傷害數字都走原本的 `HitEvent` 路徑，不直接扣血。

呈現與模擬分開。伺服器只計算飛行與傷害，不生成任何實體；`BattleProjectilePresentation` 對所有 client 多播「發射」與「結束」，各 client 自己建立本機視覺實體，以相同速度追向目標的身體中心。配對戰中，客場玩家的畫面以 `MirrorX` 反射，與單位視覺一致，因此球不會出現在鏡像之外的位置。

## 取捨

- 不選直線飛行：目標走位即可閃避，路徑上也可能誤傷其他敵人，與「戰士與射手只打出手時鎖定的目標」衝突，結果也更難預測。
- 不選「所有射手一律投射物」：血腥哈維與猴子沒有 `ball` 動畫，強制套用要補資源，也無法讓設計者逐隻決定。
- 不把球做成伺服器實體：配對戰的鏡像視覺只認 `BattleUnit`，另生成同步實體會在客場畫面出現在錯誤位置，還要另外修改 `BattleView`。
- 出手者死亡時球消失，代表擊殺射手可以攔下在途傷害。若之後想讓球繼續飛，需要改成球自己保存傷害政策並脫離 `Cancel`。

## 後果

- 傷害延後一個飛行時間（距離 ÷ 速度），攻擊間隔、攻擊命中影格與出手朝向規則不變。
- `ProjectileSpeed` 與成長率無關，不隨怪物等級改變，與移動速度、攻擊範圍相同。
- 球視覺重用 `battleviewvisual` 模型並關閉其名牌；若日後要區分排序或大小，再另建專用模型。
